# Evidence: first planted-fault test (2026-10-09)

This backs the past-tense claim in beat B03: *"When I planted fifty missing values, my check caught all fifty."*

It is a hand-run experiment for **one fault type**, not the Seeded Faults project. Nothing here was generated by Claude-written tests. I wrote the checks myself, with scripts drafted by Claude.

## What was done
1. Took the first 2,000 rows of the public NYC TLC yellow-taxi trip file for January 2024 → `trips_sample.csv`.
2. `ge_fault.py` blanked `passenger_count` in 50 random rows (fixed seed `random_state=7`) → `trips_faulted.csv`.
3. Ran the same not-null check on both files in **Great Expectations** and in **dbt**.

## Results (logs in `output/`)
| Tool | Clean sample | 50 planted nulls |
|---|---|---|
| Great Expectations 1.24.0, `ExpectColumnValuesToNotBeNull` | passed, 0 unexpected | failed, 50 unexpected |
| dbt 1.12.5 + dbt-duckdb, `not_null` | PASS | FAIL 50 |
| dbt `accepted_values` on `payment_type` (column not faulted) | PASS | PASS |

Logs were captured by re-running the scripts at 17:32 EDT on 2026-10-09, after the first interactive runs earlier that day gave the same numbers. `output/data_sha256.txt` fingerprints the data files used.

## Reproduce
Data files are not committed. From an empty folder:
```bash
python3 -m venv .venv && source .venv/bin/activate && pip install great_expectations==1.24.0 pandas pyarrow dbt-duckdb==1.11.0
curl -L -o yellow_2024_01.parquet https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_2024-01.parquet
python -c "import pandas as pd; pd.read_parquet('yellow_2024_01.parquet').head(2000).to_csv('trips_sample.csv', index=False)"
python ge_try.py && python ge_fault.py
cd dbt_try && dbt build --profiles-dir . && dbt build --profiles-dir . --vars '{trips_file: ../trips_faulted.csv}'
```
The second `dbt build` is expected to exit with an error, because the not-null test fails.

## Data
NYC Taxi & Limousine Commission trip record data, public. Downloaded 2026-10-09.
