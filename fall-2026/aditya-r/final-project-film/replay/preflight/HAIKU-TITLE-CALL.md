# Why `claude-haiku-4-5` appears in every experimental call's modelUsage

**Found:** 2026-10-25 14:02 EDT, after the main run (`runs/20261025T135900`). Every call's JSON listed two
models: `claude-opus-5` and `claude-haiku-4-5-20251001`. The pre-run "ping" listed only Opus.

**Diagnosis (Claude):** one extra call with the same flags plus `--debug-file`, on a neutral,
non-fixture input (garden-meeting notes; full output in `haiku_diag_neutral_input.json`).
- `modelUsage`: Haiku 968 in / 12 out; Opus 382 in / 158 out.
- The two API requests in the debug log (timestamps removed; full log not kept, but checked for
  credentials and none were found):

```
[DEBUG] [API:timing] dispatching to firstParty model=claude-haiku-4-5-20251001
[DEBUG] [API:timing] dispatching to firstParty model=claude-opus-5
[DEBUG] [API REQUEST] /v1/messages ... source=generate_session_title
[DEBUG] [API REQUEST] /v1/messages ... source=sdk
```

**Reading:**
- The Haiku request is the CLI generating a session title. It returns 12–18 tokens.
- The Opus request (`source=sdk`) produces the `result` text.
- Both requests are dispatched at the same moment, so the title cannot have been part of Opus's input.
- In the experiment, Opus's token counts match the top-level `usage` of each call. Its input size is
  consistent with system prompt + input + the ~250-token overhead seen in the ping.
- The ping probably had no title call because its input was one word. That is a guess, not checked.

**Consequences:**
- Every summary and opening was generated by `claude-opus-5`.
- The fixture text (synthetic) was **also sent to Haiku** for the title. No Haiku output enters the
  experiment.
- No flag was found or tried to turn the title call off.
