## 2026-10-10
- Chose the project: a log-triage CLI that proposes a root cause from backend logs, cites the exact log lines, and checks those citations mechanically. Picked it over an API breaking-change reviewer and a contract-test generator because it addresses a habit I've seen in development work: pasting errors into a chatbot and acting on the answer unchecked.
- Corrected a competitor claim before it reached the film. While brainstorming, Claude described log platforms like Datadog as tools that search logs but don't reason about cause. Checking the Datadog docs showed this was out of date: Bits AI SRE already proposes root causes and can mark an investigation inconclusive. I narrowed the value proposition from "finds root causes" to "an open, re-checkable test bench with known answers."
- Decided on Claude Code (college seat) in headless mode instead of the Claude API, so no separate API key is needed. Noted the reproducibility limit: rebuilding a run needs Claude Code access, so every diagnosis will be saved and dated.
- Chose Postgres via Docker over SQLite for more realistic database failures. Chose "database slowed" as the first scenario.
- Chose 3 runs per scenario to measure consistency. Kept the keyword-matching baseline as plan B only, to hold scope.
- Wrote PROJECT-BRIEF.md.
